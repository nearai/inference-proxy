# Pinned closure of the GPU-attestation Python packages installed in the
# runtime stage (nv-attestation-sdk / nv-ppcie-verifier, see the Dockerfile).
#
# WHY: nv-attestation-sdk and nv-ppcie-verifier pin their direct deps loosely,
# so without this file pip would resolve many transitive packages (requests,
# cffi, packaging, …) to whatever is newest on PyPI at build time. That makes
# the pip layer, and therefore the vllm-proxy-rs image digest, drift across
# build days even though it is reproducible within a single day (so the
# same-day reproducible-build.yml check cannot catch it). Pinning the full
# closure makes the install resolve identically whenever it runs.
#
# These are constraints, not requirements: the two top-level packages stay
# controlled by the Dockerfile build args (NV_ATTESTATION_SDK_VERSION /
# NV_PPCIE_VERIFIER_VERSION). The build fails unless this file lists exactly
# the packages pip installed into /usr/local/lib/python3.10/dist-packages
# (minus those two), in `pip list --format=freeze` spelling.
#
# The interpreter (python3, 3.10) and pip itself are Ubuntu packages, pinned in
# pinned-packages-runtime.txt together with the setuptools and wheel that
# build timeout-decorator, the one package installed from source (it has
# never published a wheel).
#
# REGENERATE after bumping NV_ATTESTATION_SDK_VERSION / NV_PPCIE_VERIFIER_VERSION,
# the base image or UBUNTU_SNAPSHOT:
#   1. Delete the pin lines below, keeping these comments. The check is
#      skipped while the file has no pins, and pip picks the newest versions
#      that have wheels.
#   2. ENABLE_NV_ATTESTATION_SDK=1 ./build-image.sh && docker load -i oci.tar
#   3. docker run --rm --entrypoint python3 <image id> -m pip list \
#        --disable-pip-version-check --format=freeze \
#        --path /usr/local/lib/python3.10/dist-packages \
#        | grep -viE '^(nv-attestation-sdk|nv-ppcie-verifier)==' | sort -f \
#        >> attestation-constraints.txt
#   4. Rebuild: the check now enforces the file.
#
