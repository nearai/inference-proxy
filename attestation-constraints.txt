# Pinned transitive closure for the NVIDIA GPU-attestation Python deps installed
# in the runtime stage (nv-attestation-sdk / nv-ppcie-verifier — see Dockerfile).
#
# WHY: nv-attestation-sdk and nv-ppcie-verifier pin their *direct* deps loosely,
# so pip resolves several transitive packages (cryptography, urllib3, setuptools,
# coverage, …) to whatever is newest on PyPI at build time. That makes the pip
# layer — and therefore the vllm-proxy-rs image digest — drift across build days
# even though the layer is reproducible within a single day (so the same-day
# reproducible-build.yml check cannot catch it). Pinning the full closure makes
# the install resolve identically regardless of when it runs.
#
# These are constraints (not requirements): they cap versions only for packages
# pip actually installs; they do not force-install anything on their own. The two
# top-level packages stay controlled by the Dockerfile build-args
# (NV_ATTESTATION_SDK_VERSION / NV_PPCIE_VERIFIER_VERSION).
#
# REGENERATE when bumping NV_ATTESTATION_SDK_VERSION / NV_PPCIE_VERIFIER_VERSION:
#   docker run --rm --entrypoint bash <vllm-openai base> -c \
#     'pip install --quiet --dry-run --report /tmp/r.json \
#        nv-attestation-sdk==<ver> nv-ppcie-verifier==<ver> && \
#      python3 -c "import json;[print(p[\"metadata\"][\"name\"]+\"==\"+p[\"metadata\"][\"version\"]) \
#        for p in sorted(json.load(open(\"/tmp/r.json\"))[\"install\"], key=lambda x:x[\"metadata\"][\"name\"].lower())]"'
# then drop the two nv-attestation-sdk / nv-ppcie-verifier lines.
#
